# AGENTS.md

Файл для агента, которому дали этот репозиторий. Человеку адресован
[README.md](README.md) — он подробнее и содержит обоснования решений.

## Что это

Санитизация базы MySQL: на входе дамп с персональными и конфиденциальными
данными, на выходе тот же дамп без них — со сохранёнными связями, числом
строк и числом различных значений. Открытая основа — myanon (Modified BSD,
закреплённый коммит), доработка — слой сквозной подстановки внутри
свободного текста и цикл автонастройки конфига с участием языковой модели.

Решение тестового задания, а не промышленный продукт. Границы честно
перечислены в README, раздел «Границы решения».

## Запуск

```
SANITIZE_SECRET='ключ' docker compose up --build
```

Одна команда: тесты → MySQL → исходная база → дамп → санитизация → вторая
база → восемь проверок. Код возврата 0 только если всё сошлось.

Поиск имён в свободном тексте выключен по умолчанию и требует модели.
Расшифровка такого прогона — `measurements/run_with_llm.txt`, смотреть, если
модели нет:

```
DETECT_NAMES=1 LLM_ENDPOINT=http://host.docker.internal:12434/engines/v1/chat/completions \
  SANITIZE_SECRET='ключ' docker compose up --build
```

## Тесты и самопроверки

Тесты идут первыми внутри прогона. Отдельно, без санитизации:

```
docker run --rm --entrypoint sh rusal-sanitizer-sanitizer:latest -c "python3 -m pytest /app/tests -q"
```

Из корня репозитория (пакет в `src/`, поэтому нужен `PYTHONPATH`):

```
PYTHONPATH=src python3 -m pytest tests -q
PYTHONPATH=src python3 -m sanitizer.pii_columns
PYTHONPATH=src python3 -m sanitizer.config_builder --самопроверка
PYTHONPATH=src python3 -m sanitizer.loop_guard
```

Замеры, которым нужна запущенная модель:

```
PYTHONPATH=src python3 -m sanitizer.scan_columns data/demo_dump.sql отчёт.json
PYTHONPATH=src python3 -m sanitizer.detect measure
PYTHONPATH=src python3 scripts/bench_model.py ai/qwen3:14b-q4_K_M 10 20
```

## Правила, которые здесь соблюдаются

Нарушение любого из них — дефект, а не стилистика.

- **Пустая проверка — это отказ, а не успех.** У проверки три исхода:
  норма, НАРУШЕНО, НЕ ПРОВЕРЕНО. Последний означает «сравнивать было
  нечего» и тоже даёт ненулевой код возврата. Сломанный разбор и чистая
  база обязаны различаться по выводу.
- **Вывод модели не становится исполняемым.** Модель возвращает
  типизированные находки, конфиг собирает детерминированный код, вид
  находки проверяется по белому списку `ВИДЫ` в `scan_columns`.
- **Правила конфига только добавляются.** Существующее правило внутри
  цикла не заменяется и не удаляется — иначе покрытие может молча упасть.
- **Один вид данных — один механизм.** Два механизма на одну колонку уже
  ломали сквозную замену (замерено: 3 расхождения из 186 пар).
- **Проверяющий не строится на коде проверяемого.** `checks/verify.py`
  восстанавливает карту замен заново; общие данные вынесены в
  `pii_columns.py`, от которого зависят обе стороны, а друг от друга — нет.
- **Числа в документации подтверждаются машинно.** `tests/test_readme_claims.py`
  вычисляет каждое из источника истины и сверяет с текстом README.
  Меняешь поведение — обнови README, иначе прогон не стартует.

## Чего делать нельзя

- Не коммитить `SANITIZE_SECRET` и не класть ключ в конфиг или образ. Ключ
  передаётся только переменной окружения; `sanitize.sh` создаёт временный
  конфиг с `chmod 600` и удаляет его по `trap`.
- Не отправлять данные во внешние API: модель работает локально, адрес
  задаётся `LLM_ENDPOINT`.
- Не менять `data/demo_dump.sql` руками — он порождается
  `scripts/generate_demo_dump.py` байт в байт.
- Не «чинить» падающие проверки ослаблением условия. Если проверка
  падает — падает поведение.

## Порядок вызова

Порядок задают два shell-скрипта, а не Python: модули пакета запускаются
только из них или командами фазы настройки из раздела «Тесты и самопроверки», остальное подключается
импортом.

Прогон — `scripts/entrypoint.sh`, точка входа образа:

1. `pytest` — тесты и сверка README с кодом;
2. `scripts/generate_demo_dump.py` — демо-база, загрузка в MySQL;
3. `mysqldump` — исходный дамп;
4. `scripts/sanitize.sh`, внутри два этапа:
   - этап 1 — `myanon` по конфигу `config/myanon.conf.template`;
   - этап 2 — `sanitizer.text_substitute`; импортирует `pii_patterns`,
     `sql_parse`, `pii_columns`, а при `DETECT_NAMES=1` ещё `detect` и `loop_guard`;
5. загрузка очищенного дампа во вторую базу;
6. `sanitizer.checks.verify` — восемь проверок;
7. `sanitizer.checks.determinism` — тот же ключ, тот же результат.

Настройка — вручную, раз на новую базу: `sanitizer.scan_columns` →
`sanitizer.config_builder` → человек смотрит дифф конфига.

Этот список сверяется с самими скриптами тестом `tests/test_call_order.py`:
переставят шаги в скрипте — упадёт тест, а не устареет документ.

## Где что лежит

| Путь | Что |
|---|---|
| `src/sanitizer/text_substitute.py` | слой сквозной подстановки — главная доработка |
| `src/sanitizer/pii_patterns.py` | распознавание и порождение значений строгого формата |
| `src/sanitizer/scan_columns.py` | сканер колонок, три детерминированных фильтра поверх ответа модели |
| `src/sanitizer/config_builder.py` | находки → конфиг myanon |
| `src/sanitizer/checks/` | восемь проверок и детерминированность |
| `config/myanon.conf.template` | правила по колонкам |
| `measurements/` | сохранённые отчёты замеров, на которые ссылается README |
| `tests/` | эталонный набор, фильтры сканера, пустые проверки, утверждения README |
